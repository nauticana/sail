# Sail Code Review - 2026-06-13

Scope: `README.md`, `package.json`, TypeScript sources under `src/`, and the public API exported by `src/index.ts`.

Verification performed: `npm exec tsc -- --noEmit` completed successfully. No Angular compiler/template check or unit test target is present in `package.json`, so template/runtime findings below are based on static inspection.

| SAIL-001 | Security | High | Fixed | `src/service/auth.interceptor.ts:3-8` | `authInterceptor` adds `Authorization: Bearer <jwt>` to any request whose URL contains `/api/`. | A downstream app that calls an absolute third-party URL containing `/api/` can leak the user's JWT off-domain. This is especially risky because sail is installed as a global interceptor in consumer apps. | Scope the interceptor to `RestURL.httpHost + /api/` and same-origin relative `/api/` URLs only. | SAIL-002 | Security | Medium | Won't fix (by design) | `src/service/auth.service.ts:103-118`, `src/service/auth.service.ts:235-247` | Session JWT and temporary `loginToken` are stored in `localStorage`. | Any XSS in a downstream app can steal long-lived auth material and replay it. The README documents HttpOnly cookies for trusted-device secrets, but not for the main session. | Prefer an HttpOnly, Secure, SameSite session cookie for the primary session or an in-memory access token plus refresh flow. If JWT-in-localStorage remains intentional, document the risk and required CSP/XSS hardening. |

## Resolution — 2026-06-13

Maintainer evaluation of each finding and what was changed. All fixes keep the public API backward compatible except the one behavioral change called out in SAIL-004 (a migration note was added to the README).

- **SAIL-001 — Fixed (valid).** `authInterceptor` now attaches the JWT only to the configured keel host's `/api/` URLs via the new `isKeelApiUrl()` helper (`src/service/rest_url.ts`). Third-party absolute URLs containing `/api/` no longer receive the token.
- **SAIL-002 — Won't fix (by design).** Moving the session to an HttpOnly cookie is a keel-coordinated, breaking architecture change, not a library fix. The localStorage trade-off is intentional for a token SPA; documented the XSS/CSP hardening expectation under README → *Session token storage*.
- **SAIL-003 — Fixed (valid).** `priceId` is now an optional input; `startCheckout()` omits it in `setup` mode and guards subscription/payment modes that lack a price with an inline error. Matches the documented SetupIntent flow.
- **SAIL-004 — Fixed (valid).** `verify2FALogin()` now returns `Observable<TwoFactorVerifyResponse>` (mirrors `verifyBackupCode()`); `TwoFactorVerifyComponent` drives it through `BaseAsync.run()` for loading + invalid-code UI. **Behavioral change for direct callers** — they must `.subscribe()`; migration note added to the README.
- **SAIL-005 — Fixed (valid).** `initRoutes()` calls `navigateByUrl(postLoginTarget())` — preserves a deep-linked authenticated route on refresh/bookmark and only falls back to `/dashboard` from root or a `/login` route.
- **SAIL-006 — Fixed (valid).** Added a `reportId` computed (last path segment) used for `getReport()`, title, params, and `canReport(reportId)`; the full path is kept only for the fetch URL. A `REPORT/ACCESS` grant on the report id now authorizes a namespaced route.
- **SAIL-007 — Fixed (valid).** Registration geocoding is now active only when `googleMapsApiKey` is configured (`geocodeEnabled`). Without a key, the consent + verify step is hidden, the consent validator is dropped, and submit no longer requires a successful geocode.
- **SAIL-008 — Fixed (valid).** Bumped `package.json` to `1.0.7` (the adopted keel-v1.0.7 feature level); aligned README Quick Start (`^1.0.0`), update example (`@1.0.7`), the compatibility matrix (added v0.9.x / v1.0.x), and the backend-endpoints heading.
- **SAIL-009 — Fixed (valid).** Regenerated the "What it provides" table from `src/index.ts` — added price-selector, portal, usage, status-chip, trial, seat, dunning, payout, SCA, and user-payment-method exports plus the new model types and utils.
- **SAIL-010 — Fixed (valid).** `LabelService` is a TODO stub; removed it from the advertised Services list. The export is retained (no import breakage) but no longer documented as a supported service until implemented.
- **SAIL-011 — Partially fixed.** Added `scripts` (`typecheck`, `check:templates`, `check`), the `@angular/compiler-cli` devDependency, and `angularCompilerOptions.strictTemplates` so `ngc` performs template type-checking. `tsc --noEmit` passes. The `ngc` template check could **not** be executed here (offline — `@angular/compiler-cli` isn't installed); it should be wired into CI and run there. Unit/smoke tests remain a follow-up.
- **SAIL-012 — Fixed (valid).** `apiResponseInterceptor` is now scoped to keel URLs (`isKeelUrl()`); third-party responses pass through untouched. The error-rewrite that flattened `HttpErrorResponse.error` to a string was removed, so the original ProblemDetail object reaches components — this also repairs a latent bug where `err.error.detail`/`.message` (read across the codebase) always fell back to the generic message.
- **SAIL-013 — Fixed (valid).** `BaseAsync.run()` gained an optional `onError` hook; `SocialLoginComponent` now emits `(loginError)` on backend failures, matching its documented contract.
- **SAIL-014 — Fixed (valid).** `TableLookup.resolveApi()` pipes the one-shot `getAppData()` through `take(1)`, so the lookup no longer leaves a live subscription on the ReplaySubject.
